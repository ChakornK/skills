# Brainstorming and Idea Generation

Use this reference when the user asks for an idea, suggestion, concept, option, approach, or
recommendation, including prompt, skill, or process ideas. Do not use it to force an ideation funnel
onto execution of a specific creative brief.

## Mandatory sequence

Follow every stage below, in order, before you recommend. Do not skip, summarize, merge, or silently
shrink a stage. Do not reveal or hint at the recommendation early.

1. **Frame:** State the Long-term goal, constraints, and material unknowns. Show the full breakdown under Markdown headings.
2. **Generate:** Explore distinct directions broadly; name every candidate and stop only when fresh
   novelty passes produce repetitions rather than new approaches.
3. **Compare:** Run the complete headed Markdown champion ladder below. Eliminate exactly one candidate per match.
4. **Refine:** Apply the finalist, find a concrete weakness, revise it, and test the revision.
5. **Confirm:** Apply the final version to a fresh, distinct case and assess it against the criteria.
6. **Recommend:** Only after the preceding stages reconcile, state the recommendation and remaining limits. For actions in any stage, use the bounded Immediate action plan below; after each result, update the goal and revise the remaining sequence when needed.

Before moving from comparison to refinement, count the named candidates and comparison sections aloud
in the response. If there are N candidates, there MUST be exactly N−1 headed match sections. If the count or winner
chain fails, STOP and repair it; do not advance, shortlist, or recommend. Before recommending, verify that
the full roster, every comparison outcome, the observed or simulated status of each application, the
failure-driven revision, and the fresh confirmation are all present. If any is missing, the response is
incomplete: continue in installments and withhold the recommendation. Never describe a simulated test
as observed or claim that it passed as an executed test.
## Action planning

Before acting in any stage, show these headings:

### Long-term goal
State the requested end state, constraints, evidence, uncertainties, risks, and validation criteria.

### Immediate action plan
List a numbered sequence of one to five tightly related steps, each naming the exact action and target. Restate the Long-term goal, explain how the sequence advances it, identify alternatives and the strongest objection, and predict expected and plausible unexpected results with next steps. Run the full Argument Loop on the sequence before its first step. Include every file read, shell command, write/edit/patch, test, and call in a batch as an explicit step. For every write/edit/patch step, include the exact proposed content and explanation before execution. After each result, compare evidence with prediction; if the remaining steps need revision, stop and re-plan. Otherwise continue only through the listed steps. Start a new plan after completing the sequence. This is required for user transparency and auditability; no action is exempt as routine, read-only, small, reversible, or already planned.

## Generate

Frame the goal and constraints. Explore distinct mechanisms, audiences, formats, scales, and
assumptions. Make successive novelty passes over underrepresented dimensions—such as actor, timing,
incentive, information, context, and failure response. Name distinct candidates and stop when further
angles produce repetitions rather than new directions.

## Narrow

Use a sequential champion ladder. Present the complete candidate roster by name. Do not assign IDs
or number candidates. Begin with the first named candidate as champion. Compare it with the second;
then compare each winner with the next unused candidate in roster order until every candidate has
competed. Write every match as its own headed Markdown section. In each match, name champion and
challenger; state the challenger's defining advantage and target problem; compare both candidates on
that same problem with a concrete benefit, cost, or failure mode for each; then name the winner,
explain the loser's elimination, and identify the new champion. Either candidate can win. Apply one
tie-breaker consistently.

Audit before proceeding: the first match compares the first two names; each later champion is the
previous match's winner; each remaining name appears exactly once as challenger in roster order; each
match eliminates exactly one candidate; one champion survives. Count the roster and matches: N names
require N−1 match sections. Repair every omission, duplicate, contradictory outcome, or count mismatch
before refinement. Do not proceed with a broken ladder.
## Refine and validate

Treat the champion as provisional. State observable success and failure criteria. Turn the idea into a
usable prompt, procedure, or rule and apply it to a concrete sample. For a prompt, show separate blocks
for the exact prompt, exact input, and resulting output. Apply the prompt text; do not write a plausible
answer and pretend it came from a test. Mark any application you did not actually perform as simulated.
For a procedure or rule, execute its steps and record the decisions and result.

Find and state a concrete failure or material weakness. Revise the idea to address that specific
failure, then apply the revision to a materially different sample using the same criteria. If the
revision fails, revise again and retest; do not stop at a failed result. Test a relevant stress case.
Finally, apply the final version to a fresh confirmation input that differs from every earlier sample,
show its output, and check every success criterion. Only a passing fresh confirmation permits a
recommendation within the tested scope. State external validation limits; never turn sample success into
a claim of universal reliability. Put the complete refinement record before the final recommendation.
